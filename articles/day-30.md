# Day 30 - 復盤：Claude Code Skills 真正改變的是什麼？

![Day 30 封面：產品經理與 AI 助理復盤三十天成果](https://raw.githubusercontent.com/AdaaWu/2026ithome-claude-skills/main/images/day-30/cover.png)

### 如何客觀評估 AI 工作流為團隊帶來的真實改變？

探索三十天後，團隊迎來驗收成果的時刻。

運動員集訓結束，教練會拿三十天前的體能數據逐項比對。成長要靠測量紀錄來證明。

工作流也需要這樣一次「工作流程復盤」：用執行日誌、人工微調紀錄與品質指標，檢視四個維度的實際成效。

## 復盤要看可追溯的改變

評估 FlowBoard 工作流時，我們看三件事：決策多快拿到足夠證據、修正是否即時、每項結論能否連回原始來源。

復盤包含四個維度：
- **產出效率（Efficiency）**：工廠每小時的產量。衡量任務完成時間與人工微調次數。
- **產出品質（Quality）**：出廠合格率。評估內容完整度、結構一致性與溯源能力。
- **決策品質（Decision Quality）**：航海日誌裡的航線理由。檢視團隊是否依據數據與可驗證假設推進專案。
- **系統可靠性（Reliability）**：電力系統的供電穩定率。記錄排程準時率、異常預警與補跑復原能力。

![三十天復盤流程圖：由效率、品質、決策品質、系統可靠性四項指標匯入量化指標卡片，再啟動下一輪迭代](https://raw.githubusercontent.com/AdaaWu/2026ithome-claude-skills/main/images/day-30/retrospective-metrics-flow.png)

## 做法與權衡

原因：團隊要依復盤深度與時間資源，挑選成效檢視方式。

- **方案 A：關鍵指標對照法（適合快速敏捷週會）**：比對核心指標前後數值，找出明顯改善項目與待補數據，短時間內凝聚共識。
- **方案 B：四維度證據溯源復盤法（適合季度策略檢核）**：檢視效率、品質、決策與穩定度四個維度，結合執行日誌與測試集做根因分析，制定下階段計畫。

## 執行規則

① 匯出執行日誌：匯出專案的 run、review 與 decision log，作為分析依據。
② 比對基準數據：用相同標準對照導入前後的指標變化。
③ 記錄改善案例：記錄執行中的例外與修正措施，作為規則演進依據。
④ 擬定演進目標：為下階段設定可驗證的改進假設與負責窗口。

## 結構化示範：可追溯的案例分析

以實際案例 `RUN-20260912` 為例：

```text
事件代碼：RUN-20260912
情境描述：日報排序將一則社群貼文列入首要推薦
溯源調查：
① 輸入卡片 INT-019 標示為待驗證來源
② 排序規則 flowboard-daily-intel@1.0.0 待增加證據權重上限配置
③ 人工審核階段在兩分鐘內完成確認
改進措施：
① 在 Skill 規則中增加來源證據門檻配置
② 在測試集中新增各類信號權重案例
③ 審核介面強化標示來源之可信度標籤
負責角色：產品營運負責人
驗收標準：通過回歸測試集後將 Skill 升級為 1.1.0 版
```

## 用 Prompt 執行復盤主持

```text
角色：產品工作系統復盤主持人

背景：
目標在於客觀評估流程在各項條件下的運作成效與演進空間。

輸入：
- 基準流程數據
- 執行歷程日誌（run logs）
- 人工調整紀錄
- 品質評分表
- 決策歷程紀錄
- 排程運作與補跑紀錄

任務：
① 綜合比較產出效率、產出品質、決策品質與系統可靠性。
② 為每項結論標註資料來源、樣本數量與解讀限制。
③ 找出運作良好的關鍵條件與留待完善之環節。
④ 提出下個階段可驗證的流程改進計畫。

輸出：
A. 四維度成效摘要卡片：維度名稱、對照成果、限制說明
B. 流程優化行動清單：改進項目、負責窗口、完成時限、驗收方式
C. 下階段架構演進建議：保留機制、升級條件、驗證步驟
```

### 範例輸出與核心價值

```text
成效總結：情報日報製作時間縮短至原本的三分之一，且關鍵項目維持 100% 來源可溯源性
限制說明：樣本累計 5 次執行，留待後續擴大驗證
行動項目：為 Skill 升級 1.1.0 版建立自動化回歸測試腳本
負責窗口：Product Operations Lead
完成時限：下個工作週期啟動前
```

這項復盤的價值是「讓進步看得見」。不靠感覺，用數據與紀錄推動團隊前進。

## 人類需要檢查什麼

- 確認引用的指標數據都有對應的執行日誌與時間戳記。
- 遇到待補資料，如實交代樣本限制。
- 針對異常紀錄，確認已規劃改進方案。
- 檢視下階段改進項目都已指定負責窗口與完成期限。
- 驗證審核關卡確實有把關內容品質。

## 把規則封裝成 Claude Code Skill

專案目錄結構配置如下：

~~~text
.claude/skills/workflow-retro/SKILL.md  # 復盤推論規則
~~~

在 `.claude/skills/workflow-retro/SKILL.md` 寫入配置：

~~~markdown
---
name: workflow-retro
description: 依據固定測試集、執行紀錄與人工審核歷程，復盤 Claude Code 工作流在效率、品質、決策和可靠性之成效。
---

執行原則：
① 依據專案中保存之日誌與測試資料進行客觀分析。
② 分別呈現在效率、品質、決策與可靠性之具體表現。
③ 為每項主張標明樣本數、基準線與限制條件。
④ 針對待補充資料客觀標註，留待後續累積長期數據。
~~~

執行指令：

~~~text
/workflow-retro 請讀取 docs/evals、docs/decisions 與 Git 歷史紀錄，產生成效復盤報告，列出已獲實證之成果與後續推進重點。
~~~

執行後會產出四維度評估摘要，指出流程的亮點與待改善處。
