# Day 30｜復盤：Claude Code Skills 真正改變的是什麼？

![Day 30 封面：產品經理與 AI 助理復盤三十天成果](https://raw.githubusercontent.com/AdaaWu/2026ithome-claude-skills/main/images/day-30/cover.png)

### 如何客觀評估 AI 工作流為團隊帶來的真實改變？

在持續探索三十天之後，團隊迎來了驗收成果的時刻。這就像運動員在集訓結束時站上體能檢測儀，教練會拿出三十天前的初始體能數據，逐項比對跑步秒數、心跳穩定度與動作精準度，用清晰的測量記錄見證成長。在軟體產品開發中，這項檢測就是「工作流程復盤」：依據客觀保存的執行日誌、人工微調紀錄與品質指標，全面檢視系統在產出速度、產出品質、決策清晰度與系統穩定度四個維度的實證成效評估方法。

## 復盤要看可追溯的改變

評估 FlowBoard 工作流的成效時，我們專注於三項關鍵指標：決策獲取充足證據的速度、修正機制的即時性，以及每項結論連結原始來源的完整程度。

一套專業的復盤包含四個核心維度：
- **產出效率（Efficiency）**：像工廠每小時生產的玩具數量，它是衡量任務完成所需時間與人工微調次數的量化速度指標。
- **產出品質（Quality）**：像玩具出廠時的合格率檢驗，它是評估產出內容完整度、結構一致性與溯源能力的品質指標。
- **決策品質（Decision Quality）**：像航海日誌中標註航線的決策理由，它是檢視團隊依據具體數據與可驗證假設推進專案的決策能力指標。
- **系統可靠性（Reliability）**：像電力系統的平穩供電率，它是記錄排程準時率、異常預警機制與補跑復原能力的維運穩定指標。

```mermaid
flowchart TD
  A[三十天工作流復盤] --> B[產出效率：時間與人工微調]
  A --> C[產出品質：結構完整與溯源率]
  A --> D[決策品質：假設檢驗與數據支撐]
  A --> E[系統可靠性：排程準時與補跑復原]
  B --> F[量化指標卡片]
  C --> F
  D --> F
  E --> F
  F --> G[沉澱成果與啟動下一輪迭代]
```

## 做法與權衡

原因：團隊需要根據復盤深入程度與時間資源，挑選適合的成效檢視方式。

- **方案 A：關鍵指標對照法（簡單有效，適合快速敏捷週會）**：比對核心指標前後數值，鎖定顯著改善項目與待補充數據，在短時間內凝聚團隊前進共識。
- **方案 B：四維度證據溯源復盤法（高效有用，適合季度深層策略檢核）**：全面檢視效率、品質、決策與系統穩定度四個維度，結合執行日誌與測試集進行深度根因探討，制定下個階段的演進計畫。

## 執行規則

① 匯出執行日誌：由系統匯出專案中的 run、review 與 decision log 作為客觀分析依據。
② 比對基準數據：對照導入前後在相同標準下的各項指標數值變化。
③ 記錄改善案例：詳實記錄執行過程中的例外情況與修正措施，作為推論規則演進的依據。
④ 擬定演進目標：為下個階段的流程設定具體可驗證的改進假設與對應負責窗口。


## 用 Prompt 執行復盤主持

```text
角色：產品工作系統復盤主持人

背景：
目標在於客觀評估流程在各項條件下的運作成效與演進空間。

輸入：
- 基準流程數據
- 執行歷程日誌（run logs）
- 人工調整紀錄
- 品質評分表
- 決策歷程紀錄
- 排程運作與補跑紀錄

任務：
① 綜合比較產出效率、產出品質、決策品質與系統可靠性。
② 為每項結論標註資料來源、樣本數量與解讀限制。
③ 找出運作良好的關鍵條件與留待完善之環節。
④ 提出下個階段可驗證的流程改進計畫。

輸出：
A. 四維度成效摘要卡片：維度名稱、對照成果、限制說明
B. 流程優化行動清單：改進項目、負責窗口、完成時限、驗收方式
C. 下階段架構演進建議：保留機制、升級條件、驗證步驟
```

### 範例輸出與核心價值

```text
成效總結：情報日報製作時間縮短至原本的三分之一，且關鍵項目維持 100% 來源可溯源性
限制說明：樣本累計 5 次執行，留待後續擴大驗證
行動項目：為 Skill 升級 1.1.0 版建立自動化回歸測試腳本
負責窗口：Product Operations Lead
完成時限：下個工作週期啟動前
```

這項復盤的核心價值在於「讓進步看得見、摸得著」：告別模糊的感覺，用真實的數據與紀錄引領團隊持續邁進。

## 人類需要檢查什麼

- 確認復盤引用的指標數據皆具備對應的執行日誌與時間戳記。
- 面對初期待補充之資料，客觀交代樣本限制。
- 針對運作過程中的異常紀錄，確認已規劃具體的改進方案。
- 檢視下個階段的改進項目皆已指定專屬的負責窗口與完成期限。
- 驗證審核關卡切實發揮為內容品質把關的守護作用。

## 把規則封裝成 Claude Code Skill

專案目錄結構配置如下：

~~~text
.claude/skills/workflow-retro/SKILL.md  # 復盤推論規則
~~~

在 `.claude/skills/workflow-retro/SKILL.md` 寫入配置：

~~~markdown
---
name: workflow-retro
description: 依據固定測試集、執行紀錄與人工審核歷程，復盤 Claude Code 工作流在效率、品質、決策和可靠性之成效。
---

執行原則：
① 依據專案中保存之日誌與測試資料進行客觀分析。
② 分別呈現在效率、品質、決策與可靠性之具體表現。
③ 為每項主張標明樣本數、基準線與限制條件。
④ 針對待補充資料客觀標註，留待後續累積長期數據。
~~~

執行指令：

~~~text
/workflow-retro 請讀取 docs/evals、docs/decisions 與 Git 歷史紀錄，產生成效復盤報告，列出已獲實證之成果與後續推進重點。
~~~

執行後系統會產出完整的四維度評估摘要，清晰指出流程運作之亮點與待提升之處，協助團隊持續優化工作系統。
