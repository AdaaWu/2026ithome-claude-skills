# Day 26｜設計一個越用越懂你的 AI 助理

FlowBoard 的日報 Skill 已能穩定產生草稿，換一位同事使用時，語氣、風險門檻與「重要」的定義卻全部改變。問題不是 Skill 壞了，而是團隊把偏好留在對話裡，沒有把它寫成可檢查的設定。

## 「懂你」其實是可管理的上下文

今天要解決的是：如何讓助理在不同任務中沿用一致的產品背景、格式偏好與決策界線。

不要把「記憶」想成模型像人一樣理解你。實作上，它可能來自每次附上的設定檔、應用程式保存的資料、可檢索知識庫或平台提供的對話狀態。各平台的保存期限、控制方式與適用範圍不同，不能混為一談。以 OpenAI API 為例，截至 2026-09-15，官方資料控制頁對 Responses、Files、背景模式等功能分別列出保存條件；導入時應依實際端點及組織設定核對。[官方 Data controls](https://developers.openai.com/api/docs/guides/your-data)

更安全且容易維護的起點，是建立一份人能讀、能版本管理的設定檔。它只放跨任務穩定的規則，不放每次都會變的需求，也不把個資、密碼或 API 金鑰當成「記憶」。

## FlowBoard 助理設定檔

以下為教學用模擬資料：

```text
# FlowBoard Product Assistant Profile
version: 1.0.0
owner: Product Team
reviewed_at: 2026-09-15

## 產品背景
- B2B SaaS 專案協作工具
- 主要客群：10–50 人團隊
- 當前題目：改善新成員加入工作區後的啟用流程

## 證據規則
- 將內容分為：已確認事實、教學用模擬資料、推論、建議
- 公開產品能力需附官方來源與查閱日期
- 單一社群案例只能視為待驗證線索
- 缺資料時列出待查問題，不自行補值

## 輸出偏好
- 使用繁體中文與台灣慣用語
- 先寫決策結論，再寫證據與限制
- 表格欄位需可直接交付團隊使用

## 決策界線
- 可自動：分類、格式檢查、草稿、缺漏偵測
- 需人工：需求優先級、對外發布、資料刪除、權限變更、開發承諾

## 禁止保存
- 密碼、權杖、付款資料、未經同意的個資
```

設定檔要有優先順序。一次性任務指令可以補充當日背景，但不能覆蓋資安與人工核准規則；若兩條規則衝突，助理要指出衝突並停在草稿階段。

## 可複製的啟動 Prompt

```text
角色：你是我的產品工作助理。

共同規則：
【貼上已核准的助理設定檔】

本次任務：
【任務、輸入、期限與輸出格式】

執行前：
1. 列出本次會套用的共同規則。
2. 指出缺少的必要輸入與規則衝突。
3. 若涉及對外發布、資料刪除、權限或開發承諾，只產生待審草稿。

輸出要求：
- 區分事實、推論與建議。
- 來源不足時標示「待確認」。
- 最後列出需要人類決策的項目。
```

假設使用者說：「以後看到競品有新功能就幫我排進 Roadmap。」助理不應把這句一次性要求寫回長期設定，也不應直接改 Roadmap。合適的輸出是：

```text
規則衝突：Roadmap 優先級屬人工決策。
可執行範圍：建立競品功能觀察卡與待評估假設。
需要決策：是否調整既有研究與排程。
是否寫入長期設定：否；請由設定檔 owner 審核。
```

## 讓設定「越用越準」的更新流程

每次人工修改輸出時，只記錄差異候選，不立即改設定。每週檢視：這是單次偏好，還是跨三次以上任務都成立的規則？規則是否能被明確測試？是否和既有規則衝突？通過後才開新版，並用 Day 24 的固定測試集回歸。

需要定期刪除過期內容。產品題目、目標客群或合規要求改變時，舊設定可能比沒有設定更危險。設定檔應有 owner、最後審核日期和失效條件。

## 人類要檢查什麼

檢查設定檔是否收進了不必要的敏感資料，誰能讀取與修改，以及平台是否會把內容帶入不相關任務。若使用外部知識庫或第三方工具，資料還會受到對方政策約束。OpenAI 官方也說明，傳送給第三方服務的資料適用其資料保存政策；這類邊界要在架構圖上標出。[OpenAI 資料控制文件](https://developers.openai.com/api/docs/guides/your-data)

人也要保留「忘記」能力：能移除錯誤偏好、撤回資料、回復版本。無法查看、修改與刪除的記憶，不適合承擔關鍵產品規則。

## 今天的產出物

建立一份個人 AI 助理設定檔，至少包含：產品背景、證據規則、輸出偏好、決策界線、禁止保存項目、owner、版本與審核日期。用一個正常案例、一個缺資料案例和一個規則衝突案例測試。

明天會把設定檔、Skill 與資料來源串成自動化流程。助理「怎麼工作」已經寫清楚，下一步是決定何時啟動、失敗怎麼處理，以及在哪裡停下來等人審核。
