# Day 25｜把常用任務變成你的專屬 AI Skill

![Day 25 封面：產品經理將成熟流程封裝成 Skill](../images/day-25/cover.png)

FlowBoard 團隊已經有一個通過測試的日報 Prompt，但每次使用仍要提醒同事貼哪些欄位、去哪裡找模板、輸出要存在哪裡。當一項任務有固定觸發情境、輸入、步驟與驗收方式，就值得把它封裝成可複用的 Skill。

## 先說清楚這裡的 Skill

「Skill」不是跨平台統一標準。本文把它當成一個可版本管理的任務套件：包含用途說明、必要輸入、操作規則、輸出契約、範例與測試。你可以只用 Markdown 實作，也可以轉成特定平台支援的格式。

截至 2026-09-15，OpenAI API 已提供 Skills 資源，可上傳目錄或 zip 建立 Skill，回傳物件含預設版與最新版等欄位；這是 OpenAI 的產品介面，不代表其他平台採相同結構。[官方 Create Skill API](https://developers.openai.com/api/reference/python/resources/skills/methods/create)

不要因為有一段常用 Prompt 就急著封裝。若任務仍頻繁改目標、必要資料每次不同，或成功標準說不清，封裝只會把混亂藏起來。FlowBoard 選擇日報任務，是因為它已跑過固定測試集，輸入和輸出相對穩定。

## 設計 FlowBoard 日報 Skill

![Skill 結構：指令、範例、資源、輸出契約與測試案例](../images/day-25/core-workflow.png)

以下均為教學用模擬設定。

```text
name: flowboard-daily-intel
version: 1.0.0
purpose: 將已建立來源摘要的情報卡整理成每日產品日報
use_when: 使用者提供一張以上、具 ID 與來源的情報卡
do_not_use_when: 原始資料只有網址，或要求直接發布未審核內容
required_inputs: 產品決策題目、情報卡、排序規則、涵蓋區間
outputs: 日報草稿、缺漏清單、人工審核清單
```

接著把處理規則寫成明確步驟，而不是「請專業分析」：

1. 驗證每張卡片是否有 ID、來源、日期與證據狀態。
2. 對相同事件去重，但保留所有卡片 ID。
3. 依既定四維規則評分，不自行增加權重。
4. 產生最多三則「今日必看」。
5. 將來源衝突、缺漏、單一社群案例列入待查。
6. 產出人工審核清單，不直接寄送。

輸出契約也要可以驗收：標題固定包含日期；每則必看項目必須有原始 ID、事實、推論、來源、下一步；沒有負責人時寫 `待指派`，不能自行捏造姓名。

## 範例輸入與輸出

輸入若只有：

```text
FB-I-021｜某論壇有人說競品很難用
```

正確行為不是產出「競品使用體驗普遍不佳」，而是：

```text
狀態：無法進入正式日報
缺漏：原始網址、發布日期、作者身分、具體問題
證據：單一社群線索
下一步：補齊原文後，再進來源摘要流程
```

這正是 Skill 比單一 Prompt 多出的價值：它定義何時拒絕繼續，以及失敗時要交付什麼。

## 人類要檢查什麼

Skill 的名稱和描述會影響人或系統何時選用它，因此要用具體任務命名。權限也要最小化：只需要讀情報卡的 Skill，不應取得客戶名單或發布權。任何會寄信、改資料或建立工單的動作，都應另設審核與權限層。

此外，平台支援的 Skill 可能有不同檔案結構、大小限制、執行環境與資料保存方式。採用前查當下官方文件；本文模板是設計方法，不宣稱可原封不動匯入所有工具。
