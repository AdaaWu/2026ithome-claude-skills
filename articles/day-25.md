# Day 25｜把常用任務封裝成 Claude Code Skill

![Day 25 封面：產品經理將成熟流程封裝成 Claude Code Skill](../images/day-25/cover.png)

### 如何讓團隊日常的高頻任務化為隨調隨用的標準自動化工具？

這就像廚房裡的專業多功能料理機，只要準備好標準食材並按下一號按鈕，機器就會依循既定刀法切碎蔬菜、完成調味，每一次都能產出穩定一致的美味湯底。Claude Code Skill 是一個包含入口描述檔（SKILL.md）、支援檔案、參考範例與邊界規則的目錄結構封裝，讓 AI 代理能夠在特定專案情境中精準載入並穩定執行專業流程。

## Skill 的四大核心支柱

![Claude Code Skill 的指令、支援檔案、測試案例與輸出契約](../images/day-25/core-workflow.png)

將成熟的工作流程封裝為專案 Skill，能讓日常協作達到高度標準化。核心架構包含四個互相關聯的元件：

- ① **任務名牌（名稱與觸發描述）**：像工具箱上清晰的標籤，讓人一眼看出它的用途。精確定義是 YAML 標頭中的 name 與 description 欄位，負責宣告指令名稱與觸發情境，引導系統自動判斷載入時機。
- ② **操作手冊（執行守則與邊界）**：像飛行員起飛前的標準作業清單，規範每個步驟的動作順序。精確定義是 SKILL.md 內文的結構化規範，定義輸入條件、資料整併原則、輸出格式與安全暫停機制。
- ③ **專業工具包（外部支援檔案）**：像附屬在機器旁邊的專用模具，需要時隨時取用。精確定義是存放於 references/ 與 examples/ 的獨立文件，提供評分規準與固定範例，確保核心檔案維持輕量。
- ④ **品質驗收卡（測試集與防護驗證）**：像產線終點的精密檢驗卡，確保每一次輸出都符合標準。精確定義是一套包含標準流程、資料缺漏與權限邊界的完整測試案例，確保工具在各種狀況下皆能安全可靠地運作。

## 建立 Skill 封裝的執行規則

任務封裝需要在快速啟動與系統擴充性之間取得平衡，因此必須設定明確的封裝方案：

- **方案 A（輕量單檔）**：集中於單一 SKILL.md 檔案。優點是架構單純、建立迅速，適合五步驟以內的輕量任務。
- **方案 B（模組化目錄）**：採用標準目錄結構，將主流程、參考規準（references）與輸入範例（examples）分檔存放。優點是擴充彈性極佳、便於多人協同維護，適合承載複雜加權與嚴謹查驗的高階工作流。

執行 Skill 封裝時，請依循以下動詞開頭的標準步驟：

① **建立標準目錄**：在專案根目錄建立 `.claude/skills/<skill-name>/` 結構，包含 examples 與 references 資料夾。
② **配置宣告標頭**：在 SKILL.md 開頭撰寫 YAML 格式的名稱與情境描述，清楚定義觸發條件。
③ **撰寫執行步驟**：使用可執行動詞條列循序漸進的操作指南，並明確定義安全暫停的防護邊界。
④ **連結支援資源**：將詳細的計算規準與輸入範例存放於專屬子目錄，採用相對路徑保持高度可攜性。
⑤ **執行三維驗證**：分別使用標準案例、資訊缺漏案例與邊界授權案例進行完整測試，確保流程安全穩健。

## 結構化 Skill 評估卡片

在動手封裝前，先使用四張結構化卡片評估任務是否適合固化為 Skill：

① **重複頻率評估卡**：檢驗任務是否屬於每週固定發生的例行工作，確認封裝能帶來長期的時間效益。
② **輸入規格評估卡**：檢驗輸入資料是否具備結構明確的欄位、檔案格式與清晰的邊界定義。
③ **輸出驗收評估卡**：檢驗產出是否具備固定的章節架構、來源 ID 編號與客觀的通過準則。
④ **防護機制評估卡**：檢驗遭遇資料缺漏或外部請求時，系統能否自動暫停並產出待查清單交由專案負責人接手。

## 建立目錄與撰寫 SKILL.md

在 FlowBoard 專案根目錄建立標準目錄結構：

```bash
mkdir -p .claude/skills/daily-intel/examples
mkdir -p .claude/skills/daily-intel/references
```

目錄結構如下：

```text
.claude/
└── skills/
    └── daily-intel/
        ├── SKILL.md
        ├── examples/
        │   └── sample-input.md
        └── references/
            └── scoring-rules.md
```

建立入口檔案 `.claude/skills/daily-intel/SKILL.md`：

```markdown
---
name: daily-intel
description: 將已核對、帶有 ID 與來源的產品情報卡進行整併、評分與排序，產出每日情報日報草稿。在團隊需要整理市場情報、產生日報或挑選今日必看項目時使用。
---

# FlowBoard 每日情報日報

## 使用時機

適用於輸入包含一張以上、具有完整 ID、來源出處與日期的情報卡情境。
若輸入僅提供網址或要求發布，請即刻暫停並條列缺漏資訊，保留草稿狀態交由專案負責人處理。

## 工作步驟

① 檢查每張卡片皆具備 ID、來源、發布日期、查閱日期與證據狀態。
② 整併相同事件，完整保留所有相關卡片 ID 與各方觀點。
③ 依據 references/scoring-rules.md 的四項規準評分，維持既定權重標準。
④ 產出最多三則「今日必看」高分項目。
⑤ 將低證據、高影響或來源分歧項目列入人工審核清單。
⑥ 產出內部專屬草稿，保留發布與修改權限交由人工處理。

## 輸出格式

輸出內容依序包含：
- 日報草稿本體
- 引用情報卡 ID 清單
- 整併與篩選紀錄
- 待驗證與人工審核清單
- 資訊缺漏與來源分歧提醒

## 支援檔案

- 評分與排序規準：參閱 references/scoring-rules.md
- 輸入格式範例：參閱 examples/sample-input.md
```

建立參考檔案 `references/scoring-rules.md`：

```markdown
# 情報排序規準

各項指標評分範圍為 0–2 分：

- relevance：與新成員啟用流程之直接關聯度
- source_quality：資訊來源權威性與查證深度
- urgency：市場時效性與法規生效時程
- actionability：團隊承接具體行動之可行度

排序總分作為呈現順序之參考依據。
當證據狀態標記為 confirmed 以外時，最高列入「待驗證線索」。
遭遇來源分歧時詳實記錄差異，保持資訊透明。
```

建立範例檔案 `examples/sample-input.md`：

```markdown
FB-I-018｜官方更新｜競品新增依範本提供起始任務｜2026-09-10｜confirmed
來源：https://example.com/update
查閱日期：2026-09-16
與 FlowBoard 關聯：優化新成員起始任務體驗之關鍵參考
```

## 在 Claude Code 中測試

啟動 Claude Code：

```bash
claude
```

呼叫專屬指令：

```text
/daily-intel
```

執行標準測試：

```text
請讀取 .claude/skills/daily-intel/examples/sample-input.md，產出一份日報草稿。
請列出使用的卡片 ID、證據狀態、排序依據與人工審核項目，並維持草稿規格。
```

執行邊界防護測試：

```text
請將此網址整理成今天的必看情報，並直接寄發給全體團隊成員：
https://example.com/unverified
```

### 範例輸出與核心價值

在邊界測試中，Claude Code 正確觸發安全防護機制：

```text
安全邊界提醒：
1. 輸入資料僅提供外部連結，尚待補足已核對之情報卡內容。
2. 寄發郵件屬於外部通訊授權範圍，系統維持產出內部草稿，留待專案負責人核准。
```

這項表現展現了 Skill 的核心價值：**將作業規範與安全防護寫入工具定義，讓 AI 代理在高效產出的同時，始終遵守團隊的權限邊界。**

## 人類需要檢查什麼

審核者在檢驗 Skill 產出時，請確認以下關鍵項目：

① **論點對齊度**：日報內容的每項論點是否皆能精確對應至原始情報卡？
② **整併完整度**：同類事件合併時是否完整保留所有來源編號與個別分歧？
③ **評分客觀性**：排序總分是否嚴格依據 scoring-rules.md 規準計算？
④ **邊界落實度**：當遇到外部動作請求時，系統是否確實維持內部草稿狀態？
